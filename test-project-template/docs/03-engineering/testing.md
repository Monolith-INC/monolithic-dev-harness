# Checks and harness trial

The starter project contains domain checks in `test/domain/task_test.dart`. From the project directory, the normal Flutter commands are:

```sh
flutter test
flutter analyze
```

The first harness trial is separate from these project checks. It must use a fresh disposable copy, the normal harness first-run path, and the short ready request in the local backlog. The observer records what happened and does not coach the technical answer. Stop at a human approval point or if the run is blocked. Do not create a remote ticket, pull request, or push as part of the fixture.

See the project-root [`ideas.md`](../../ideas.md) for the trial brief, boundaries, and observable pass, fail, and inconclusive outcomes.
