# Six-stage onboarding implementation

Authorized by the human to generate this plan and execute it. This changes the harness,
not the acceptance fixture or its application. Preserve the concurrent acceptance report.

## Contract

Discovery → Planning → Hardening → Preparation → Confirmation → Execution.
Record evidence and decisions throughout; preparation assembles the final bundle.
No version-control prerequisite or question applies before execution. Native controls are
attempted first, with async and chat fallback. Only consequential unresolved choices block
their dependent work. User suspension disables every harness veto. Recorded approvals remain
valid for their unchanged context; changed circumstances require consultation.

## Delivery units

1. Audit shared enforcement boundaries and classify accidental dead ends. Make suspension
   bypass vetoes before parsing, session binding, settings validation or delegated guards.
   Preserve genuine answer observation without allowing observation failures to veto tools.
2. Make checkpoints writable while paused; accept the six semantic stages while retaining
   legacy checkpoints. Remove VCS checks from pre-execution planning instructions.
3. Add bilingual planning-depth and method-selection gates after discovery and before drafting.
   Light uses self-review and focused checks; Standard adds contextual risk/edge-case review;
   Hardcore adds adversarial, preservation and verification reviews. Use BMAD's contextual
   shortlist, Reshuffle, List all and Proceed; add agent recommendations.
4. Assemble requirements, spec, risk findings and selected companion documents into a manifest
   with purpose, read trigger and location. Draft tracker artifacts before publication. Persist
   the implementation plan with all load-bearing references. Present one final content-bound
   confirmation before execution; independent external writes retain contextual authorization.
5. Fix evidence-saving and question-transport recovery at shared boundaries. Quoted heredoc
   data must not become executable substitutions; actual executable substitutions stay guarded.
   Do not exempt arbitrary interpreters or source edits under a documentation path.
6. Update the main-flow documentation and diagram, run focused and full regression checks,
   review changes for security and correctness, record checkpoints, commit and push to PR #37.

## Verification

Test suspension with protected-state paths, direct hook calls, missing settings, stale sessions
and delegated guards. Test paused evidence checkpoints and legacy stage loading. Validate every
gate in English and pt-BR. Exercise quoted/unquoted heredocs and executable shell input separately.
Keep active-mode anti-fabrication, source protection and contextual approval negatives intact.
Static regression results do not establish live native capture. Preserve the trial's genuine
blocking and async capture evidence and report its quota interruption honestly.

## BMAD basis and deliberate differences

Adopt Build's evidence-first investigation and Code Map; PRD's stakes calibration, concern scan,
reviewer triage and input reconciliation; Advanced Elicitation's contextual catalog; Spec's lean
kernel, companions, coherence and preservation checks. The three depth profiles and unified
manifest are harness orchestration. Native transport and complete suspension are harness duties.
Do not copy upstream's pre-planning VCS gate or repetitive approvals.
